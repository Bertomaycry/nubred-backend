NuBred Platform · Technical Overview

AI Pipeline for Project Creation

How uploaded documents become a reviewed, confirmed agricultural project — and how the assistant supports the process before, during, and after creation.

Governing principle

The AI never decides anything. It proposes structured data with a citation for every single field. A human confirms or corrects it — and only confirmed data becomes project truth.

The pipeline at a glance

Project creation moves through four stages. The first two are automated, the third is where the Variety Manager takes control, and the fourth begins once the project exists.

Stage 1 — Document intake

Stage 1

Upload and prepare the documents

No AI is involved at this stage — and no AI cost is incurred by uploading.

  • The Variety Manager uploads contracts, Capitolato, annexes, correspondence and spreadsheets in their original formats (PDF, Word, Excel, CSV, email).
  • Files are transferred directly into private encrypted storage. They never pass through the application server, and they are never given a public address.
  • Each document is verified on arrival, then converted to text page by page, preserving the page number and position of every passage.
  • This page-level index is what makes precise source citation possible in every later stage.
Stage 2

AI extraction produces a draft project

The AI reads the documents once and proposes a complete first draft.

  • Each section of the project is extracted by a separate, specialised AI request, so instructions stay focused and results stay comparable.
  • Every request combines four inputs: NuBred's domain glossary, the phase framework, the standard clause library, and the section's own extraction rules — together with the document text.
  • The AI is constrained to a fixed output structure rather than asked for free text. It cannot return prose, and it cannot invent extra fields.
  • Every returned value is validated a second time before storage. A malformed result fails visibly and is retried, instead of quietly corrupting a project.

Nothing here is treated as fact. The result of this stage is a draft. No value has entered the project record yet.
Stage 3

Human review, with the assistant alongside

The Variety Manager works through the five sections in order. This is where the assistant is used during creation.

  • “Why?” on any field instantly shows the source document, the page, and the exact sentence the value was taken from. Nothing is a black box.
  • Conflicting values open a conversation. The assistant states the disagreement plainly — “the supply agreement says 60 days, the annex says 30” — and asks which applies.
  • Missing values are requested, not guessed. The Variety Manager can supply them in the conversation or enter them directly.
  • Plain-language corrections are supported. An instruction such as “the delivery window is 30 days, not 60” updates the field.
  • Every change is recorded with the previous value, the new value, who made it, why, and whether it came from the assistant or was entered manually.
Confirmation is gated. A section with unresolved blocking issues cannot be confirmed, and that rule is enforced by the server — not merely hidden in the interface. On confirmation, a locked copy of exactly what was approved is stored permanently, and the data enters the live project record.
Stage 4

Project assistant, after creation

Proposed design — not yet built. Included here for agreement on the approach.

  • Once the project exists, the assistant answers questions about it: “what are our obligations to the nursery in Phase 2?”, “which protocol parameters are eliminatory?”
  • Crucially, it answers from the confirmed project record — the data a human has already approved — and not by re-reading the original documents.
  • This matters: re-reading the source documents would reintroduce exactly the uncertainty that the review stage existed to remove, and could contradict what was approved.
  • Answers carry the same citations produced during extraction, so the assistant can point to the originating clause and page.
  • The assistant is read-only. Changing approved project data always goes back through the recorded review-and-confirm process, so the audit trail is never bypassed.

How the AI reports confidence

Every extracted field carries one of four states. Conflict and absence are treated as legitimate, expected outcomes — the system is designed to admit uncertainty rather than guess.

Confirmed

Taken from a signed document or otherwise definitive source.

Provisional

Taken from a non-binding source such as an email, draft or meeting note.

Conflicting

Two documents disagree. Raised for resolution; cannot be silently averaged.

Missing

A required value was not found in any document. Flagged, never invented.

Four guarantees built into the system

Nothing is accepted automatically

AI output is held separately from the project record. Only an explicit human confirmation moves a value into the live project.

Every field is traceable to a source

Each value stores its originating document, page number and verbatim quotation, viewable at any time.

Every change is attributed

Who changed what, from which value to which value, when, why, and whether by hand or through the assistant.

Every AI version is recorded

Each extraction stores a cryptographic fingerprint of the exact instructions used and the model that ran them — so any value can be explained months later.

Extensibility

The five sections are self-contained. Each carries its own data structure, its own validation rules and its own AI instructions, registered in one central place. Adding a further section — as anticipated in the roadmap — means adding one new self-contained unit; it does not require changes to the extraction engine, the review process or the assistant.

Data handling and confidentiality

Project documents are held in a private, access-controlled store. They are reachable only through short-lived, individually issued links, and are never publicly addressable. Access is scoped so that a user of one organisation cannot reach another organisation's projects, and this is enforced at the data layer rather than in the interface.

All AI access is routed through a single internal interface, which means the underlying model provider can be changed — or, for enterprise clients with their own data-processing requirements, replaced with the client's own provider account — without redesigning the platform. Production processing will run on commercial provider terms under which submitted content is not used to train models.
